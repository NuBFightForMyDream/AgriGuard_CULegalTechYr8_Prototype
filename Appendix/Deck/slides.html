System Flow: 1 ดีลจากต้นจนจบ

ใครเรียก API ไหน Backend ทำอะไร สถานะเปลี่ยนเป็นอะไร และทุก request ผ่านด่านอะไรบ้าง
ใครAPIBackend ทำอะไรสถานะหลังจบ
1ผู้ซื้อPOST /purchase-requestsสร้างคำขอซื้อ เลือกซื้อจากรายเดียว (SINGLE) หรือหลายราย (MULTI) + จำนวนผู้ขายสูงสุดOPEN
2ผู้ซื้อGET /purchase-requests/{id}/matchesกรองเงื่อนไขบังคับ → ให้คะแนนถ่วงน้ำหนัก 5 ปัจจัย พร้อมเหตุผลรายข้อรายการสวนเรียงตามคะแนน
3ผู้ซื้อPOST /offersตรวจว่าไม่เกินปริมาณที่ยังขาด · audit + แจ้งเตือนเกษตรกรPENDING
4เกษตรกรPOST /listings/{id}/allocation/preview
  → /allocation/confirm		ล็อกแถว listing ด้วย SELECT … FOR UPDATE กัน overbook · optimizer แบ่งของ · สร้าง HarvestLock + การจองที่มีวันหมดอายุAWAITING_CONFIRMATION
5ผู้ซื้อPOST /contracts/{id}/acceptterms → canonical JSON → SHA-256 terms_hash · บันทึกการยอมรับ + ชื่อที่พิมพ์ลงนาม · ปิดข้อเสนออื่นตามโหมดซื้อCONFIRMED
6เกษตรกรPOST /contracts/{id}/lotsสร้างล็อต LOT-… + QR token สำหรับหน้า trace สาธารณะ (ไม่มีข้อมูลส่วนบุคคลหรือราคา)HARVESTED
7เกษตรกร ผู้ซื้อPOST /lots/{id}/dispatch · /receiveบันทึกน้ำหนักตอนส่งและตอนรับIN_TRANSIT → QC_PENDING
8ผู้ตรวจ QCPOST /lots/{id}/inspections
  (+ /lots/{id}/ai-grade)		เทียบเกรดกับสัญญา → discrepancy flags · ตรวจครบทุกล็อต → สร้าง settlement snapshotPAYMENT_PENDING
9ผู้ซื้อPOST /settlements/{id}/payments
+ Idempotency-Key		Net = Σ(กก. × ราคาตามเกรด) − มัดจำ · ถ้า key ซ้ำจะไม่บันทึกซ้ำPAID
